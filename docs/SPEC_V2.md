# 1. 执行摘要
一个好的英语软件不是把背单词、刷题、听力、阅读和录音做成若干孤立页面，而是把诊断、目标、课程路径、真实输入、主动练习、口头/书面输出、具体反馈、间隔复习、复测和下一步计划连接成可持续闭环。
图 1-1  英语学习闭环
| 本次调研的核心结论 目标产品应同时具备“课程路径”和“自由练习中心”；能力体系不应只按听说读写划分，还要独立管理词汇、语法、发音/拼读、拼写/听写、翻译/中介、流利度和考试策略。 |

## 最终产品应达到什么程度
| 维度 | 完整标准 |
| 学习方向 | 首次诊断、目标、目标日期、每日时间预算、课程路径、检查点、跳过和补救 |
| 内容输入 | 教材、网页、PDF、EPUB、音频、视频和字幕进入统一资源库；支持原文、解析版本和版本历史 |
| 能力训练 | 词汇、语法、阅读、听力、口语、写作、翻译、考试共享通用活动与评分底层 |
| 长期记忆 | 单词、错题、句子、语法和听写进入统一复习；支持 FSRS、积压、轻松日和冲刺 |
| 学习数据 | 所有模块写统一学习事件，才能生成掌握度、推荐原因、趋势、负荷和阶段报告 |
| 系统寿命 | 数据本地、可备份、可校验、可迁移、可导出；即使软件停止维护，学习资产仍可读取 |

## 不应复制的商业机制
• 答错扣心、虚拟货币和为日活制造的压力
• 强制账号、强制云同步和强制 AI
• 排行榜、公开社区、课程商城和广告
• 只显示“正确答案”却不提供错误类型、补救和复习
• 页面很多但学习记录、知识点、复习和报告互不相通

# 2. 调研范围、方法与证据等级
本报告对比 47 个代表性产品、开源项目和行业标准，覆盖路径式综合学习、真实材料阅读、间隔记忆、发音口语、写作修改、考试训练、儿童启蒙、内容制作、离线平台、题目交换、学习事件、电子书、字幕、可访问性和本地数据安全。

## 调研原则
• 优先使用产品官方帮助中心、官方功能页、官方标准和开源仓库说明。
• 产品宣传只用于确认其公开功能，不把市场宣传直接当作学习效果证据。
• 同一能力至少比较两类以上产品，避免照搬单一产品的信息架构。
• 把“学习为什么需要”与“客户端怎样实现”分开分析。
• 把商业产品、开放标准、开源组件和免费学习资源分开，避免把对标误解为依赖。
• 所有结论必须能落到数据、状态、异常、离线行为和验收步骤。

## 证据等级
| 等级 | 使用方式 |
| A：官方标准/技术规范 | 用于确定能力框架、题目模型、字幕、EPUB、可访问性和备份等硬约束。 |
| B：官方产品文档 | 用于确认成熟产品公开存在的入口、流程、模式和状态。 |
| C：开源项目说明与代码结构 | 用于判断本地实现和二次开发可行性。 |
| D：产品设计推论 | 由多个来源共同支持后形成，报告中明确标记为本项目设计选择。 |
| 研究输出 本报告最终形成 397 条逐功能规范。每条均包含功能编号、用户目的、入口与正常流程、实现与核心数据、异常/边界/验收、优先级与阶段。 |

# 3. 当前项目基线与核心缺口
当前英语刷题机已经具备本地题库、按年份和随机整篇练习、考研/四六级主要客观题型、听力、自动判分、错题重做、单词收藏、Word/PDF 草稿导入、ESQ 交换和 SQLite 本地存储。这些应保留为考试与题库子系统，而不是推倒重来。[S01]

## 可直接复用的资产
| 资产 | 处理策略 |
| 题库、试卷、篇目、题目和稳定选项键 | 保留现有数据和判分；逐步映射到通用活动模型。 |
| 练习会话与答案历史 | 保留；补写统一学习事件和知识点证据。 |
| 错题统计与重做 | 保留；接入统一复习、掌握度和补救路径。 |
| 单词本与语境出现 | 保留；升级为词元/词形/词义/卡片/FSRS 模型。 |
| Word/PDF/ESQ 导入 | 保留解析链路；增加收件箱、原文件、解析版本、校验和回滚。 |
| 本地 SQLite 和文件目录 | 保留本地优先；增加一致备份、完整性检查、迁移和开放导出。 |

## 决定底层是否需要重构的关键缺口
• 当前核心仍是“试卷→篇目→题目→选项”，无法自然承载阅读任务、听写、录音、写作、翻译和课时内容块。
• 缺少学习阶段、课程、模块、课时、Can-do 目标、知识点前置关系和路径检查点。
• 缺少统一活动、评分、反馈、尝试历史和学习事件模型。
• 缺少资源收件箱、原文/解析文分离、内容版本、草稿、发布、校验和回滚。
• 缺少词义层掌握、卡片模板、目标保持率、复习负荷和积压处理。
• 缺少完整的写作修改、录音日志、字幕时间轴、搜索、导出和系统健康检查。
| 架构判断 现有刷题机应成为“考试与题库内核”，上方新增课程、资源、通用活动、知识图谱、统一复习和学习事件层。这样才能保留既有价值并避免未来每增加一种活动都修改巨型练习页面。 |

# 4. 好英语软件的判定标准
本项目不以“功能入口数量”判断完成度，而以学习闭环、数据连通、长期可用和个人控制权判断。
| 判定维度 | 本项目的实现标准 |
| 学习目标明确 | 每个课程、模块和课时都写清完成后能做什么，而不是只显示知识点名称。 |
| 输入真实且有支架 | 材料可以来自真实文章、书籍和媒体，但必须有难度、词汇、任务和输出支架。 |
| 主动回忆 | 学习者必须在答案出现前尝试提取，而不是只重复阅读和播放。 |
| 输出不可缺失 | 说、写、翻译和造句必须成为正式活动，不能永远停留在选择题。 |
| 反馈具体 | 指出错在哪里、为什么、证据是什么、下一步做什么；不只给分和答案。 |
| 复习自动生成 | 课时、阅读、听写、错题和输出错误自动产生后续复习，不要求用户手抄。 |
| 推荐可解释 | 今日任务和薄弱项应告诉用户为何被安排。 |
| 内容可制作 | 私人教材也需要分段、活动、版本、校验和回滚。 |
| 本地与可迁移 | 核心断网可用；数据可备份、导出和在未来软件中读取。 |
| 可访问和低干扰 | 键盘、焦点、缩放、字幕、字号、减少动画和免打扰是正式功能。 |

## 完整度的四个层次
| 层次 | 不算完成 | 算完成 |
| 页面 | 只有入口、占位页、演示数据 | 真实资料可完成正常、空数据和失败流程 |
| 功能 | 只支持一次成功操作 | 保存、重启、撤销、删除、恢复和历史均可验证 |
| 学习 | 只给即时结果 | 能生成反馈、复习、掌握度和下一任务 |
| 系统 | 只在当前电脑当前版本可用 | 可备份、迁移、导出、检查和回滚 |

## 5.2 对标的正确使用方式
| 不是“功能拼盘” 同一功能只能在统一数据模型中存在一次。例如收藏单词无论来自刷题、阅读、字幕还是写作，都必须写入同一词汇、语境、卡片和复习系统。 |
• 商业产品的成熟入口和反馈流程可以参考，但不引入付费、排行、虚拟货币和强制云端机制。
• 开源项目可用于技术验证，但不能把多个完整应用直接拼成不可维护的客户端。
• 开放标准用于约束内部模型和导出能力，不要求第一版一次实现全部标准细节。
• 任何对标功能只有在适合个人本地学习、与现有数据兼容并有明确验收时才进入范围。

# 6. 八类关键对标结论

## 6.1 课程路径与自由练习：Duolingo、Babbel、Busuu
• 课程路径解决‘下一步学什么’，自由练习解决‘我今天只想练听力/错题/发音’。二者必须同时存在，不能把所有功能塞进同一课程地图。
• 课时完成后应自动产生词汇、句子、错题和知识点复习项；用户不需要再次手工抄入复习中心。
• 章节检查点不仅给分，还决定是否可跳过、是否需要补救、哪些低级内容可标记为已掌握。
• 学习计划应以目标、目标日期、学习日和日时长为输入，并给出预计完成日期；不能只用连续打卡替代计划。
对标来源：S02,S03,S04,S06,S07,S08

## 6.2 真实内容输入：LingQ、Readlang、Language Reactor、FluentU
• 资源导入是一级能力：网页、文章、书籍、音频、视频和字幕必须进入统一收件箱，再经过清洗、分段、标注和课程关联。
• 点词查询应是极短操作；收藏时必须自动保存词义、原句、资源、章节和音视频时间点，形成可追溯语境。
• 阅读与听力应共享句子级数据模型。文本句子可关联字幕时间轴、标准音频、词汇、语法、笔记和复习卡。
• 真实内容不能只‘播放/展示’，要有分级、支架、理解任务、词汇练习和输出任务，才会成为可学习内容。
对标来源：S20,S21,S22,S23,S24

## 6.3 长期记忆：Anki、Quizlet、Vocabulary.com
• 笔记与卡片必须分离：一条词汇笔记可生成英译中、中译英、听音拼写、例句挖空、搭配和词形多张卡。
• 调度不只有‘下次日期’，还要管理新卡上限、遗忘重学、顽固卡、暂停、积压、轻松日、目标保持率和未来负荷。
• 同一单词的不同词义必须独立掌握，避免认识高频义却误判为掌握全部词义。
• 复习结果要回流课程、阅读、听力和考试报告，而不是形成孤立卡片岛。
对标来源：S28,S29,S30,S31,S32

## 6.4 口语与发音：Speak、Speechling、ELSA、Rosetta Stone
• 口语训练分四层：模仿跟读、脚本式角色对话、任务式情景表达、开放自由对话。前两层无需 AI 也可高质量实现。
• 基础闭环为听标准音→录音→快速对比→自评/自动检测→重录→将难句加入复习。
• 语音转文字只能衡量‘说了什么’，专业发音评分还需音素、重音、语调、节奏和非母语者语料，必须作为高级 Provider。
• 用户在安静/无法说话环境中应能切换听力或打字模式，学习计划要尊重现实场景。
对标来源：S05,S10,S13,S14,S15,S16

## 6.5 写作迭代：Write & Improve、LanguageTool、Grammarly、DeepL Write
• 写作模块的核心不是一次给总分，而是审题、提纲、初稿、规则检查、逐条修改、二稿、错误归档和重写。
• 建议必须可接受、忽略、撤销和解释；接受后进入版本差异记录，用户能看到自己修改了什么。
• 离线版本先以拼写、语法、标点、重复词、句长和量表自评为主；深层语义反馈可作为可选 Provider。
• 系统不应默认替用户整篇重写，否则削弱语言生产和检索练习。
对标来源：S38,S39,S40,S41,S42

## 6.6 考试准备：TOEFL、IELTS、Cambridge、EF SET
• 考试中心要分成题型熟悉、专项训练、分项测试、完整模考和结果复盘，不应把所有试卷放在一个列表。
• 诊断与正式模考不同：诊断要估计分技能能力和薄弱知识；模考要复现时间、顺序、不可查词等限制。
• 每种题型需要操作示例、策略、提示、范例答案、评分量表和多次尝试记录。
• 成绩报告至少包含总分、分项、题型、知识点、用时、信心、目标差距和下一步任务。
对标来源：S43,S44,S45,S46,S47,S48

## 6.7 儿童模式：Khan Academy Kids、Duolingo ABC、Read Along、Starfall
• 儿童启蒙不是成人页面换大按钮；需要独立外壳、低文字密度、语音指令、图片反馈和更短活动。
• 路径应从音素意识、字母音、拼读、视读词、手写和可读故事逐步推进，内容难度必须同步。
• 朗读反馈应低压力、鼓励性、可重复，并允许离线；对错误只提示当前目标，不展示复杂评分。
• 儿童内容必须有年龄适宜性、图片/音频质量和家长可见的学习记录，但个人版不必做家长账户。
对标来源：S49,S50,S51,S52,S53

## 6.8 内容制作与自适应：Oppia、H5P、Kolibri Studio
• 资源、课程和活动是三个层次：同一资源可被多个课程复用；课程编排活动；活动通过渲染器呈现和评分。
• 作者后台必须支持草稿、预览、校验、发布、版本、差异和回滚，否则长期整理资料会不可维护。
• 错答应按错误类型进入不同反馈或补救步骤；活动引擎需要返回结构化结果，而非仅 true/false。
• 新增题型应通过插件/渲染器扩展，避免在一个巨型页面里不断增加条件分支。
对标来源：S54,S55,S56,S57

# 7. 目标产品定义、边界与反模式
| 正式产品定义 一套 Windows 本地桌面客户端，能够容纳个人合法获得的英语资源，组织课程与知识点，训练多项语言能力，记录每次学习证据，自动安排复习，并保证数据长期可迁移。 |

## 正式范围
| 范围 | 决定 |
| 使用者 | 单用户；无需注册登录；可以建立多个学习目标或档案快照。 |
| 运行方式 | Windows 独立客户端；核心功能断网可用；本地后端只监听 127.0.0.1。 |
| 数据 | SQLite + 本地文件；私人教材、录音和学习历史默认不出本机。 |
| 内容 | 开放资源 + 个人已购/已获资源 + 自建内容；按需导入而非一次预装全部。 |
| AI | 非必需；只作为可关闭 Provider；无 AI 时不得出现假语义评分。 |
| 协作 | Codex/Claude 只实施已编号规范；产品范围和优先级由本报告确定。 |

## 反模式清单
• 将 Vue 界面等同于网页版正式产品；正式交付必须是独立桌面窗口。
• 给每种题型建立独立数据库和页面，导致学习记录无法统一。
• 把 AI 当作知识库、评分器和内容编辑器的唯一实现。
• 导入后覆盖原始文件，或重新解析时丢失笔记和定位。
• 只按正确率更新掌握度，不区分题型、间隔、难度、信心和输出层级。
• 只有累计学习时长，没有未来复习负荷、保持率和知识点证据。
• 未完成模块仍出现在导航，形成大量空页面和不可用按钮。

## 推荐技术边界
| 层 | 推荐实现 | 硬约束 |
| 桌面外壳 | Tauri 2 或等价轻量 WebView 外壳 | 双击启动；单实例；不显示黑框；可管理 sidecar。 |

| 数据库 | SQLite + 版本化迁移 | 事务、外键、一致备份、完整性检查和回滚。 |
| 文件资产 | 受管数据目录 + 哈希索引 | 原文件只读；解析版本、标注和导出分离。 |
| 搜索 | SQLite FTS 或可替换本地索引 | 索引可重建，不作为唯一数据来源。 |
| Provider | 词典/TTS/ASR/OCR/语法/AI 接口 | 不可用时核心功能降级而非崩溃。 |

## 启动和关闭协议
| 阶段 | 必须执行 |
| 启动 | 检查单实例→读取配置→检查数据目录→必要时迁移前备份→数据库健康检查→启动本地后端→建立会话令牌→打开窗口。 |
| 运行 | 定期保存草稿和位置→后台任务可取消→写入失败可重试→显示 Provider 状态。 |
| 关闭 | 停止新任务→保存进行中状态→等待或取消后台任务→提交事务→必要时自动备份→关闭后端和子进程。 |
| 崩溃恢复 | 识别上次异常退出→检查数据库和临时文件→恢复草稿/会话→显示恢复结果。 |

| 稳定键原则 题目、词义、句子、课时和资源都应使用跨数据库稳定键。内部自增 ID 只用于本机性能，不能成为导入导出、版本迁移和学习历史关联的唯一依据。 |

# 35. 跨模块统一业务规则
| 规则 | 统一要求 |
| 稳定键与版本 | 学习记录永远引用稳定键和发布版本；内容修改不允许静默改变历史题意。 |
| 原始数据保护 | 原文件、原始作答、录音、作文版本和事件日志不可被自动摘要替代。 |

| 删除与恢复 | 课程、资源、题库、笔记和录音默认先进入废纸篓；永久删除有影响预览。 |
| 时间与时区 | 事件保存 UTC 和本地时区；跨夏令时/换电脑仍能正确生成今日任务。 |
| 评分与自评分离 | 规则分、人工分、自评分和 AI/Provider 分必须分开存储和显示。 |
| 推荐可解释 | 今日任务、薄弱项和补救都保存规则版本和原因。 |
| Provider 降级 | 外部能力不可用时保留文本、草稿和原始输入，允许稍后处理。 |
| 隐私默认 | 录音、作文、教材和使用日志默认本地；任何导出/上传都必须显式操作。 |
| 可访问性 | 所有核心操作提供键盘方式、可见焦点和非拖拽替代。 |
| 测试夹具 | 每种导入、题型、媒体、迁移和恢复都维护真实最小测试资料。 |

## 为什么时长不能按页面数量估算
• 同一功能要同时完成数据、正常流程、失败恢复、迁移、导出和测试
• 媒体、字幕、录音和时间轴会产生复杂状态
• 内容版本修改后需要迁移高亮、笔记、复习和历史
• 统一活动、评分、事件和掌握度是跨模块基础，不是一个页面
• 真实教材、大文件、中文路径、异常退出和恢复必须实际验证

# 38. 测试、验收与发布闸门

## 缺陷等级
| 等级 | 定义 | 发布规则 |
| P0 | 数据丢失、数据库损坏、无法启动、备份不可恢复、隐私外泄 | 立即停止其他工作；必须修复。 |
| P1 | 核心旅程中断、评分错误、旧功能严重退化、状态无法恢复 | 发布前必须为 0。 |
| P2 | 局部错误但有明确绕行，或非核心格式兼容问题 | 可记录发布，但需有计划。 |
| P3 | 文案、轻微布局和低影响体验问题 | 进入后续小版本。 |

## 每个功能的五层验收
| 层 | 必须验证 |
| 数据层 | 字段、约束、迁移、稳定键、版本、删除/恢复和导出。 |
| 接口层 | 正常、空、非法输入、超时、取消、重复请求和幂等。 |
| 页面层 | 加载、空数据、错误、重试、键盘、焦点、窄窗口和高缩放。 |
| 学习层 | 能产生正确反馈、复习项、知识点证据和下一任务。 |
| 系统层 | 重启、异常退出、备份恢复、换目录、旧数据库和 Provider 不可用。 |

## 核心端到端回归集
• 导入 PDF/DOCX/EPUB/音频/字幕→重启→资源仍可学习→重新解析不丢标注。
• 阅读→收藏多义词→生成不同卡片→FSRS 复习→回到原文语境。
• 做题→产生错题→关联知识点→补救→延迟复测→掌握度变化。
• 听写→逐词差异→跟读录音→保存多次尝试→难句进入复习。
• 写作→初稿→规则检查→修改→版本差异→错误句进入复习。
• 模拟考试→中断恢复→交卷→分项报告→错题重做→目标差距更新。
• 创建备份→损坏/删除工作数据→在空环境恢复→完整性检查通过。
| 发布闸门 P0=0、P1=0；旧数据迁移成功；备份在空环境恢复成功；核心端到端回归通过；未完成入口全部隐藏；已知问题公开记录。 |

# 39. 结论与必须冻结的产品决策
| 决策 | 冻结内容 |
| D-01 | 正式产品是 Windows 本地客户端，开发时浏览器调试不等于交付形态。 |
| D-02 | 现有刷题机保留为考试内核；不以现有试卷模型承载全部课程活动。 |
| D-03 | 课程路径与自由练习中心并存，且共享同一学习数据。 |
| D-04 | 能力模型至少覆盖听、说、读、写、词汇、语法、发音/拼读、拼写/听写、翻译/中介和考试策略。 |
| D-05 | 所有活动使用统一作答、保存、提交、评分、反馈和事件模型。 |
| D-06 | 资源原文件、解析版本、发布版本和标注分离；内容有版本、校验和回滚。 |
| D-07 | 复习统一使用可替换调度器，首选 FSRS；所有推荐可解释和人工覆盖。 |
| D-08 | AI 不是核心依赖；任何 AI 分数必须标明来源和置信度。 |
| D-09 | 核心数据默认本地；开放导出和一致备份是 P0 功能。 |
| D-10 | Codex 和 Claude 只实现本文编号功能；新需求必须先更新规范版本。 |

## 最终建议
先用三周完成技术 PoC 和范围冻结，再按依赖顺序实施。不要让两个模型同时“自由发挥”整个产品；每个模块先稳定数据和状态，再做页面和视觉。系统从第一阶段起就用真实教材、真实题库和真实备份做验收。
| 最终评价 这套规范追求的不是“拥有最多按钮”，而是让个人资源、真实学习行为、反馈、复习、掌握度和长期数据在一个客户端中连成可持续体系。 |

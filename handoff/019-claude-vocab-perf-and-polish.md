- 日期：2026-08-17T17:30:00+00:00（UTC）
- 关联：用户反馈"页面很卡+UI 丑"；回执 017 §3 的后端请求优先级提升
- 需要对方行动：是（分页参数与 scope=collected 提升为 W2 内必做）

## 1. 卡顿根因（实测）

`GET /api/vocabulary?status=all` 一次返回 **6163 条 / 5.3MB JSON**，前端曾全量渲染 6163 个列表 DOM 节点；搜索框每次击键（250ms 防抖后）重新拉取全量 5.3MB。

## 2. 前端已修（本推送）

1. 窗口化渲染：首屏 120 条，滚动到底部附近自动 +120（滚动事件判定，不用 IntersectionObserver——隐藏页签/不合成帧时 IO 不触发，不可靠），"加载更多"按钮兜底。DOM 总节点 ~40k → 1167（50 倍缩减），实测 120→240→360 渐进正常。
2. UI 整修：统计卡选择器覆盖 `<a>`（修复"到期复习"卡裸奔样式）+ 图标化 + accent 强调色；提示条、词书徽章、加载提示改为统一样式类，去除散落的 inline style。

## 3. 你的两个接口改动优先级提升（W2 内必做）

前端窗口化只解决渲染，**5.3MB 传输问题必须服务端解决**：
1. `GET /api/vocabulary` 支持 `limit/offset`（契约 §1 分页约定），counts 不受分页影响。
2. `scope=collected`（判定标准见 018 §3）作为默认——个人视角下数据量回到几十条，传输问题在常用路径上消失；scope=all + 分页覆盖词书浏览场景。

## 4. 与 W2 批次的边界

不动你 in-flight 的 wrong/tasks/reports/backup 工作；上述两点可作为该批次的收尾项或紧随的小批次。

# handoff — Codex × Claude 协作回执

两个模型不共享上下文，本目录是唯一的直接通信渠道。**每次开工先读回执，每次收工必写回执。**

## 规则

1. 文件名：`NNN-{codex|claude}-<主题slug>.md`，NNN 取当前目录最大编号 +1（三位零填充）。拉取后若发现与对方撞号，不用改名，阅读顺序以文件头日期为准。
2. 回执只增不改：不得编辑或删除任何已有回执（包括自己的）；要更正就写一条新回执引用旧编号。
3. 开工流程：`git pull` → 读所有比自己上次收工时更新的回执 → 再看 Issue 和契约文档。
4. 收工流程：写回执 → 与代码同一个 PR 提交（或单独提交到 develop-v1）。
5. 契约变更（API_CONTRACT / DATA_MODEL / V1_SCOPE）**不能只靠回执生效**：回执里提出 → 用户确认 → 改契约文档，三步缺一不可。回执里可以标注"待用户确认"。

## 文件头模板

```markdown
# NNN ｜ 发件人 → 收件人 ｜ 主题
- 日期：2026-08-17T12:00:00+00:00（UTC）
- 关联：Issue #n / PR #n / 契约文档章节
- 需要对方行动：是（列清单） / 否（纯通报）

## 内容
（做了什么 / 变了什么 / 卡在哪 / 需要对方做什么）
```
